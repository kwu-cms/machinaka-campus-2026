# テスト版 Web サイト本番化に向けた情報確定のお願い

まちなかキャンパス 2026 の公開用サイト（リポジトリルート直下の `index.html` ほか一式）を本番公開するにあたり、**掲載内容を正式版として確定**するため、学科内で情報の収集・校正をお願いします。  
以下は **上映・展示・イベント** の 3 プログラムごとのチェックリストです。該当担当の方は各項目を確認し、確定稿または修正指示を出してください。

---

## 共通（依頼の受け口と反映の流れ）

**目的**  
テスト段階の仮文言・仮データをやめ、来場者向け・学科として問題ない表現にそろえる。

**回答の受け口**（運用に合わせて記入）

- [ ] 集約担当: _______________
- [ ] 提出期限: _______________
- [ ] 連絡手段（例: Slack チャンネル名・メール）: _______________

**本番反映のざっくりした流れ**

- **上映**: `data/movies.csv` の更新と、必要に応じて `index.html` / `js/main.js` の静的文言・定数の修正を Git にコミットする。
- **展示**: 現状は `index.html` 内の HTML を直接編集し、画像は `images/` に配置する。
- **イベント**: 本サイトは実行時に **Google スプレッドシート**から CSV を取得しています（URL は `js/main.js` の `SITE_CONFIG.eventsCsvUrl`）。**スプレッドシートの 1 行目（列名）を変更しない**でください。列名はプログラム側のキーと完全一致している必要があります。

**注意（共通）**

- 誤字・表記ゆれ（会場名・作品タイトル・全角半角）をそろえる。
- 未確定のまま掲載しない運用にするか、暫定表記のルール（例:「（仮）」の付け方）を決める。

## 1. 上映（Screening）

**データの所在**

| 種別 | パス・参照 |
|------|------------|
| 作品データ（CSV） | `data/movies.csv`（`js/main.js` の `SITE_CONFIG.moviesCsvUrl`） |
| 静的文言・初期スライド | `index.html` の `#screening`（会場ラベル、プログラム名、導入文、外部リンク、フォールバック用スライド） |
| 日別見出しの時間・会場（共通表記） | `js/main.js` 内の `MV_PROGRAM_SLOT_TIME` / `MV_PROGRAM_SLOT_VENUE`（現状: `17:00～19:10` / `元町映画館`） |

**`movies.csv` の列（1 行＝1 作品）**  
コードが参照する列名は次のとおりです。

- `ID`
- `上映日`
- `タイトル`
- `監督`
- `尺（分）`
- `メタ（卒制等）`
- `概要`
- `サムネイルパス`
- `表示順`

**担当・期限**

- [ ] 期限: _______________

### チェックリスト（上映）

**CSV（`movies.csv`）**

- [ ] 掲載作品の行が、当日プログラムと一致している
- [ ] 各作品の `上映日` が正しい（土／日の振り分け）
- [ ] `タイトル`・`監督`・`尺（分）`・`メタ（卒制等）` に誤りがない
- [ ] `概要` が事実とトーンの両面で問題ない（公開用に確定稿）
- [ ] `サムネイルパス` が実ファイルと一致し、画像の利用権・解像度が問題ない
- [ ] `表示順` が各日内で意図した並びになっている

**静的ページ・コード**

- [ ] `index.html` の会場表示（元町映画館）が正式表記と一致している
- [ ] 特別上映プログラム名（例:「南女シネマ」）が正式名称である
- [ ] 導入文（上映の説明段落）が最新かつ来場者向けに適切である
- [ ] 元町映画館への外部リンク URL が正しい
- [ ] パンフレット等の **開催時間帯表記** と、サイト上のスロット表記（`MV_PROGRAM_SLOT_TIME`）を一致させる必要がある場合、Web 担当へ定数変更を依頼する
- [ ] 上映用サイネージ（`?signage=screening`）を使う場合、その文言・運用に追加の確定事項がないか

## 3. イベント（Event）

**データの所在**

| 種別 | パス・参照 |
|------|------------|
| 本番データ（実行時） | Google スプレッドシート → `js/main.js` の `SITE_CONFIG.eventsCsvUrl` で指定された CSV エクスポート |
| 列名・バックアップの辞書 | `data/events.csv`（リポジトリ同梱の例。**スプレッドシート 1 行目を正**とする） |
| 簡易テンプレ | `data/events_template.csv`（列が本番 CSV と異なる場合がある。編集はスプレッドシート側を優先） |

**スプレッドシート（本番 CSV 想定）の列**  
`events.csv` に基づく列名の一覧です。**プログラムが参照する説明列のキーは `説明（200文字程度）` と完全一致**している必要があります（`js/main.js` の `DESC_KEY`）。

- `ID`
- `カテゴリ`（例: `lecture` / `workshop` / `permanent` など。小文字で統一）
- `イベント名`
- `担当分野`
- `日付1行目`
- `時間2行目`
- `会場`（※現行の一覧 UI では未使用の列だが、データ整備・将来利用のため確定しておくことを推奨）
- `タグ`
- `画像（Teamsで共有）`（※表示ロジックは別途確認。パス整備用）
- `説明（200文字程度）`（**必須キー**）
- `文字数`
- `申込要否`
- `申込URL`
- `公開状態`
- `表示順`
- `登壇者`

**時間列と登壇者列について**  
`時間2行目` に時刻が入っていない文字だけが入ると、プログラム側で列の解釈がずれる救済ロジックが動く場合があります。**時刻は `時間2行目` に HH:MM 形式で入れる**運用を推奨します。

**公開状態について**  
現行コードでは **`公開状態` 列によるフィルタは行っていません**。ドラフト行をサイトに出したくない場合は、スプレッドシート側の運用（行を消す／別シートに移す）か、Web 側の実装追加が必要です。運用方針を決めて記載してください。

- [ ] 期限: _______________

### チェックリスト（イベント）

**掲載単位**

- [ ] サイトに出す行の `ID`・`イベント名` が確定している

**各列の内容**

- [ ] `カテゴリ` が意図した値（lecture / workshop / permanent 等）である
- [ ] `日付1行目` が正式な日付表記である
- [ ] `時間2行目` が正式（未定の場合は「時間未定」等、運用ルールに沿う）
- [ ] `登壇者` が正しく該当イベントに紐づいている（時刻が別列に入っていないか再確認）
- [ ] `担当分野` の表記が統一されている
- [ ] `タグ` の付け方がルールどおりである
- [ ] `説明（200文字程度）` が公開用の確定稿である（列名を変えない）
- [ ] `申込要否`・`申込URL` が実態と一致している
- [ ] `表示順` が意図した並びである
- [ ] `公開状態` の運用（ドラフトをどう扱うか）が学科内で共有されている
- [ ] `会場`・画像列を今後サイトに表示する場合の文案・パスを準備した（任意）
