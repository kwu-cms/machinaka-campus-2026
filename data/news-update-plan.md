# お知らせ（`news.json`）更新計画

SNS投稿スケジュールをベースに、**サイト用の短文**だけを `data/news.json` に追記する手順書です。  
Instagram の全文・ハッシュタグは載せず、**重複させない**前提で整理しています。

---

## JSON にコメントは書ける？

**標準の JSON にはコメント構文はありません**（`//` や `/* */` を入れると `JSON.parse` でエラーになり、サイトのお知らせも表示されなくなります）。

運用で使える代替:

| 方法 | 用途 |
|------|------|
| **このファイル（`news-update-plan.md`）** | 予定・ドラフト・「いつ追記するか」のメモ（推奨） |
| 各 item の `"_note"` キー | 投稿テーマなどのメモ（`js/news.js` は `date` / `dateDisplay` / `text` だけ参照するため **画面には出ません**） |
| `news.json` を JSONC で編集 | エディタ用。GitHub Pages の `fetch` には **コメント入りのまま置かない** |

---

## 追記のルール

1. **配列の先頭**（`items` の 1 件目）に新しいお知らせを挿入する（新しい順）。
2. **`date`**: ソート用 `YYYY-MM-DD`（サイト公開日＝お知らせに載せる日）。
3. **`dateDisplay`**: 画面表示（例 `2026.06.12`）。省略時は `date` から自動生成。
4. **`text`**: 1〜3文程度。URL はそのまま書くとリンク化される。Instagram は `@mediastudies_kwu` / `@konan_wu.cinema` のように書く。
5. **常設の SNS 案内**（下記「常設」ブロック）は、他の告知が増えたら **配列の末尾** に移動して重複感を減らす。
6. SNS と **同じ日に必ず載せる必要はない**（サイトは要約・確定情報向け）。表の「Web」列が ○ の日だけ追記を想定。

---

## 常設（すでに公開済み・または末尾に置く）

```json
{
  "_note": "SNS案内・常設。新規告知を足すたびに items の最後へ移動",
  "date": "2026-06-06",
  "dateDisplay": "2026.06.06",
  "text": "最新の告知・制作の様子は Instagram で発信しています。展示・イベント・制作風景は @mediastudies_kwu、上映「南女シネマ」は @konan_wu.cinema をご覧ください。"
}
```

## コピペ用ブロック（投稿日ごと）

`items` の **先頭** に、該当日になったら以下を 1 件ずつ追加。  
`//` で始まる行は **JSON に含めない**（この md 用のメモ）。
